C

  • Header core/include/taco/taco.h, C11
  • C API 3, library 0.14.2
  • C++23, on Karu 0.2.3, libcurl and OpenSSL

libtaco is the reader core used by Python, R and Julia. It opens ZIP, FOLDER and TACOCAT datasets, checks their contracts, and generates DuckDB SQL. It does not run queries or write datasets.

DuckDB reads the metadata Parquet files and builds file locations from their rows. libtaco does not link DuckDB or a Parquet library. Beyond the CoZIP index and metadata, it reads only byte ranges requested through taco_profile or taco_fetch. The JavaScript reader uses a separate implementation. The C header declares 18 functions, grouped below by purpose.

A complete program

The program opens the single-partition ZIP of Major TOM Core-DEM, asks libtaco for the wide view, runs a query over it with DuckDB's C API, and copies the file of the highest sample with taco_fetch.

#include <taco/taco.h>
#include <duckdb.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static const char *URL = "https://data.source.coop/major-tom/core-dem/"
                         "core-dem_MT3000km_0001D_0003L.zip";

/* Runs over the relation "dataset", the view taco_sql generates. */
static const char *QUERY =
    "SELECT count(*)::VARCHAR, arg_max(id, \"geoenrich:elevation\"),"
    " max(\"geoenrich:elevation\")::VARCHAR,"
    " arg_max(\"dem.rumi::location\", \"geoenrich:elevation\")"
    " FROM dataset WHERE \"geoenrich:admin_countries\" = 'Peru'"
    " AND \"geoenrich:elevation\" > 4500";

/* Prints each download once, when it completes. */
static void progress(const char *phase, uint64_t done, uint64_t total, void *user) {
    (void)user;
    if (total > 0 && done == total)
        printf("%s: %llu bytes\n", phase, (unsigned long long)total);
}

/* Copies a VARCHAR cell of the first row into out. */
static void cell(duckdb_data_chunk chunk, idx_t col, char *out, size_t size) {
    duckdb_string_t *v = duckdb_vector_get_data(duckdb_data_chunk_get_vector(chunk, col));
    snprintf(out, size, "%.*s", (int)duckdb_string_t_length(v[0]), duckdb_string_t_data(&v[0]));
}

int main(void) {
    taco_dataset *dataset = NULL;
    char *view = NULL, *sql = NULL;
    duckdb_database db = NULL;
    duckdb_connection con = NULL;
    duckdb_result result;
    duckdb_data_chunk chunk = NULL;
    char count[32], id[64], elevation[32], location[512];
    unsigned long long offset = 0, length = 0;
    int start = 0, failed = 1;

    if (taco_api_version() != TACO_API_VERSION) {
        fprintf(stderr, "libtaco has C API %d, expected %d\n", taco_api_version(), TACO_API_VERSION);
        return 1;
    }
    printf("libtaco %s, C API %d\n", taco_version_string(), taco_api_version());
    taco_set_progress(progress, NULL);

    /* 1. Open the archive. NULL selects TACO_CACHE_DIR, then the platform cache. */
    if (taco_open(URL, NULL, &dataset) != TACO_OK) {
        fprintf(stderr, "taco_open: %s\n", taco_last_error());
        goto done;
    }
    printf("container %s, levels", taco_dataset_container(dataset));
    for (size_t i = 0; i < taco_dataset_level_count(dataset); i++)
        printf(" %s", taco_dataset_level(dataset, i));
    printf(", structure %s\n", taco_dataset_structure(dataset, 0));

    /* 2. Generate the wide view: one row per sample, with file locations. */
    taco_read_options options = {0};
    options.pivoted = 1;
    options.location = 1;
    const taco_dataset *datasets[] = {dataset};
    if (taco_sql(datasets, 1, &options, &view) != TACO_OK) {
        fprintf(stderr, "taco_sql: %s\n", taco_last_error());
        goto done;
    }
    printf("taco_sql: %zu bytes of SQL\n", strlen(view));

    /* 3. Run the query with DuckDB, the view bound as a CTE named dataset. */
    size_t size = strlen(view) + strlen(QUERY) + 32;
    sql = malloc(size);
    if (!sql)
        goto done;
    snprintf(sql, size, "WITH dataset AS (%s) %s", view, QUERY);
    if (duckdb_open(NULL, &db) == DuckDBError || duckdb_connect(db, &con) == DuckDBError)
        goto done;
    if (duckdb_query(con, sql, &result) == DuckDBError) {
        fprintf(stderr, "duckdb: %s\n", duckdb_result_error(&result));
        duckdb_destroy_result(&result);
        goto done;
    }
    chunk = duckdb_fetch_chunk(result);
    duckdb_destroy_result(&result);
    cell(chunk, 0, count, sizeof count);
    cell(chunk, 1, id, sizeof id);
    cell(chunk, 2, elevation, sizeof elevation);
    cell(chunk, 3, location, sizeof location);
    printf("%s samples in Peru above 4500 m, highest %s at %s m\n", count, id, elevation);
    printf("%s\n", location);

    /* 4. Copy that sample's dem.rumi: /vsisubfile/<offset>_<size>,<archive>. */
    if (sscanf(location, "/vsisubfile/%llu_%llu,%n", &offset, &length, &start) != 2 || !start)
        goto done;
    taco_fetch_item item = {location + start, offset, length, "highest.rumi"};
    if (taco_fetch(&item, 1) != TACO_OK) {
        fprintf(stderr, "taco_fetch: %s\n", taco_last_error());
        goto done;
    }
    failed = 0;

done:
    duckdb_destroy_data_chunk(&chunk);
    duckdb_disconnect(&con);
    duckdb_close(&db);
    free(sql);
    taco_free(view);
    taco_close(dataset);
    taco_shutdown();
    return failed;
}

The progress callback prints the metadata download and final file copy. The 2,697,870 metadata bytes come from three ranges at the end of the 1.23 GB archive: COLLECTION.json (7,033 B), METADATA/sample.parquet (1,309,304 B) and METADATA/children.parquet (1,381,533 B). DuckDB reads those local copies.

On a second run, libtaco checks the archive's 8-byte CoZIP integrity hash and reuses the cached metadata. Only taco_fetch reads a payload: it copies the highest sample's 42,283-byte dem.rumi into highest.rumi.

Build and link

libtaco needs CMake 3.21+, a C++23 compiler, the extern/karu submodule, libcurl 7.83+, OpenSSL 3 and a thread library. make core configures and tests the build, then copies the library into python/taco/_lib/. On Homebrew systems it sets OPENSSL_ROOT_DIR from brew --prefix openssl@3.

git submodule update --init extern/karu
make core

# or by hand
cmake -S core -B core/build -DCMAKE_BUILD_TYPE=Release -DTACO_BUILD_TESTS=ON
cmake --build core/build --parallel
ctest --test-dir core/build --output-on-failure

  • The build writes libtaco.dylib, libtaco.so or taco.dll to core/build/. cmake --install puts it in lib/ (the DLL in bin/) and the header in include/taco/. There is no CMake package file, so link the library by name and set an rpath: -Icore/include -Lcore/build -ltaco -Wl,-rpath,$PWD/core/build.
  • Only the 18 taco_* functions are exported. Karu and the rest of the C++ code stay hidden inside the library.
  • A development build links the system libcurl and OpenSSL dynamically. Here otool -L lists /usr/lib/libcurl.4.dylib and Homebrew's libcrypto.3.dylib.

A tag libtaco-v<version> publishes a GitHub release with libtaco-<version>-<platform>.tar.gz for linux-x86_64, linux-aarch64, macos-aarch64, macos-x86_64 and windows-x86_64, plus a .zip for Windows. Each holds include/taco/taco.h, the library in lib/ or bin/, LICENSE, karu-LICENSE and README.md. The Julia package downloads these archives.

Conventions

  • Every string passed in or returned is NUL-terminated UTF-8. Paths are UTF-8 on every platform, Windows included. A relative local path resolves against the working directory.
  • The caller owns every string, array and struct it passes, and they only need to live for the call. libtaco copies what it keeps.
  • taco_open, taco_sql and taco_profile set their out-parameter to NULL before anything else, so it is NULL after a failure.
  • A getter given a NULL handle returns NULL or 0, and an index past the count returns NULL.

Errors

The calls that can fail return a taco_status: taco_open, taco_sql, taco_profile and taco_fetch. No C++ exception leaves the library; each call turns it into a status and a message. taco_last_error() returns the message of the latest failed call on the calling thread. A successful call does not clear it, so read it only after a status other than TACO_OK.

StatusValueReturned for
TACO_OK0Success.
TACO_ERR_INVALID1A NULL argument, a bad read option, a source that is not a valid TACO dataset (another cozip profile, a broken index, an invalid COLLECTION.json, a taco:version other than 3.0.0), a URI Karu does not accept, a TACO_CACHE_SIZE that is not a number of bytes, or a fetch offset past the end of the object.
TACO_ERR_IO2A transport failure, such as a network, TLS, authentication or server error. A missing local file. A failed write to the cache, the temporary directory or a fetch target.
TACO_ERR_NOT_FOUND3A remote object that does not exist.

taco_open decides the container from the source, as Containers describes:

  • A local directory with COLLECTION.json and METADATA/ is a FOLDER. One with .tacocat/COLLECTION.json, or a .tacocat folder itself, is a TACOCAT. Any other local path is opened as a ZIP.
  • A URI whose cache entry is complete and still matches the origin is opened from the cache with the container it had.
  • A URI ending in .zip, in any case and ignoring the query, is a ZIP.
  • A URI that names a directory is read as one: a trailing /, a last component .tacocat, a bucket or host with no path, a hf:// repository, a source:// product, or a file:// directory. libtaco reads its COLLECTION.json, or .tacocat/COLLECTION.json when that is missing, and calls it a TACOCAT when the collection has taco:sources.
  • Any other URI is probed as a cozip archive first and read as a directory when it is not one. When the probe is refused with an authentication error, libtaco tries the directory, and reports the first error if that fails too.

A ZIP must use CoZIP binary version 1 and profile 2, with COLLECTION.json in its index. The collection must declare taco:version 3.0.0, a non-empty valid taco:structure, and exactly one taco:metadata entry per level (spec 7.6). A TACOCAT lists ZIP partitions as normalized relative paths in taco:sources (spec 7.5).

libtaco rejects COLLECTION.json files larger than 64 MiB, and one that repeats a key in an object or holds a number beyond the finite double range, such as 1e400. It does not decode Parquet, so use taco.validate to check schemas and rows (Validate).

Generating SQL

typedef struct {
    const char *idx;               /* NULL, "5" or "[0, 100]" */
    const char *level;             /* NULL, or one level read raw */
    int pivoted;                   /* nonzero: one row per sample */
    const char *const *files;      /* NULL, or structure declarations */
    size_t file_count;
    int location;                  /* nonzero: compute file locations */
} taco_read_options;

taco_status taco_sql(const taco_dataset *const *datasets, size_t count,
                     const taco_read_options *options, char **out_sql);

taco_sql reads only the handles and touches no file. It returns one statement in *out_sql, which the caller releases with taco_free. datasets holds count handles, at least one and none NULL.

FieldMeaning
idxNULL for every sample, "5" for the sample with index 5, "[0, 100]" for indices 0 to 99. Non-negative integers, spaces allowed, and a start no larger than the end. For several datasets it filters the index across all of them. It is ignored when level is set.
levelNULL for the joined view. Otherwise one of the names taco_dataset_level returns, read raw: every column of that Parquet file, the internal: columns included. pivoted and location do not apply.
pivotedNonzero for the wide shape, one row per sample with a column per file, as read returns it. Zero for the long shape, one row per file.
files, file_countNULL for every file. Otherwise an array of file_count declarations exactly as taco_dataset_structure returns them, which keeps only those files. Refused with level, and with a name the structure does not have.
locationNonzero to compute taco:location. In the wide shape, zero reads only sample.parquet and fills the location and generated file columns with typed NULLs, so the schema stays the same. In the long shape, zero leaves out the taco:location column.

A zeroed taco_read_options asks for the long shape without locations. Set pivoted and location to 1 for the shape of read.

  • Wide. A WITH clause names the local Parquet levels. A LEFT JOIN LATERAL pivots child rows into {file}::location and extension columns such as dem.rumi::header. SQL builds locations from ZIP offsets or FOLDER paths without fetching payloads. It percent-encodes paths appended to HTTP URLs. DuckDB's error() rejects FOLDER paths with empty, . or .. components, a leading slash or a backslash, and TACOCAT partitions absent from taco:sources.
  • Long. One UNION ALL BY NAME branch per child level, each joined up to the sample level: source_file for a TACOCAT, taco:sample_index, id, path, taco:location, then the fields of every level sorted by name. Folder rows are left out, and a field declared at two levels, in any letter case, takes the value and the spelling of the deeper one.
  • Level. One SELECT over that level's Parquet file.

A single dataset's statement has no ORDER BY. A source list combines statements with UNION ALL BY NAME, adds source_file for each part, and renumbers taco:sample_index in list order. It then orders the wide result by that index.

Raw levels in a source list remain unordered. Their internal:current_id and internal:parent_id values continue across sources, as in TACOCAT, so parent joins cannot cross source boundaries. A sample's internal:current_id equals its taco:sample_index. When source filenames are unique, source_file uses them; otherwise it uses full source paths.

libtaco does not check that several datasets belong together. The bindings compare their collections first, as Read describes, and refuse a TACOCAT in a list. A C caller should do the same with taco_dataset_collection.

With the handle of the program above, a raw level gives the shortest statement:

taco_read_options raw = {0};
raw.level = "sample";
char *sql = NULL;
if (taco_sql(datasets, 1, &raw, &sql) == TACO_OK)
    puts(sql);
taco_free(sql);
SELECT COLUMNS(lambda c: c != 'cozip:location' AND c != 'taco:location' AND c != 'taco:sample_index') FROM read_parquet('cache/.open-<host>-<pid>-<n>/METADATA/sample.parquet', hive_partitioning = false)

All shapes exclude stored cozip:location, taco:location and taco:sample_index columns because the reader computes them. The example path is relative because TACO_CACHE_DIR was; it names a process-owned snapshot and changes between runs.

DuckDB treats [, ], ? and * as glob syntax, so libtaco writes them as [[], []], [?] and [*] in a file path. hive_partitioning = false also prevents a folder like id=7/ from replacing a column value.

Running the SQL

libtaco returns text and never runs it. Run it in the same process with a DuckDB connection of your own. The bindings expose it the way SQL describes, one relation for the dataset and one per level. Python, for example, sends DuckDB this statement:

WITH "dataset" AS (<wide statement, location on>),
     "sample" AS (<level sample>),
     "children" AS (<level children>)
SELECT * FROM (
<the user's query>
) AS taco_query
  • The statements use read_parquet, COLUMNS with a lambda, LEFT JOIN LATERAL, UNION ALL BY NAME, list(... ORDER BY ...) and regular expressions. The bindings require DuckDB 1.5: Python and R ask for 1.5.5 or newer, and Julia for DuckDB.jl 1.5 or a later 1.x.
  • DuckDB reads only the local Parquet copies. Payloads are read later from the locations, by GDAL, Rumi, taco_fetch or any client that reads byte ranges (Open a file).
  • A statement names the copies by path, so it stays valid only while they exist: until the process that generated it exits, for a local ZIP and a remote source alike. Generate it again in each process instead of storing it.

Profiles and byte copies

FunctionBehavior
taco_profile
(source, &name)		Reads the size of the object, refuses one below 32,819 bytes, reads its first 58 bytes, checks the __cozip__ header and returns "none", "flat", "taco" or "unknown:<n>" in *name. It does not read the index or check the hash. Release the name with taco_free. inspect(source, "profile") in the bindings calls it.
taco_fetch
(items, count)		Copies each item's byte range into its file, creating parent directories. items may be NULL when count is 0.
typedef struct {
    const char *uri;      /* local path, URI or VSI path */
    uint64_t offset;
    uint64_t length;      /* 0: from offset to the end */
    const char *path;     /* the local file to write */
} taco_fetch_item;
  • uri is anything Karu reads, the VSI forms included, so the archive part of a location works as it is: the program above passes /vsicurl/https://.... A file:// URI is percent-decoded into the local path it names first.
  • A length of 0 reads the size of the object and copies to its end. An offset past the end is refused.
  • Every target is created or emptied before the first byte is read, so a call that fails can leave empty or partial files.
  • Bytes are read in pieces of at most 8 MiB, grouped into Karu batches of at most 64 MiB, and appended to the files in order, so at most 64 MiB of file data is in memory at a time.
  • taco.export in Python copies payloads with it.

Progress

typedef void (*taco_progress_fn)(const char *phase, uint64_t done, uint64_t total, void *user);
void taco_set_progress(taco_progress_fn callback, void *user);
  • One callback serves the whole process. NULL restores the built-in bar, one line per phase on stderr, drawn only when stderr is a terminal.
  • phase is "downloading <name> metadata" while taco_open copies metadata, a local ZIP included, and "downloading <n> file" or "downloading <n> files" in taco_fetch. done and total count bytes. A phase starts at done 0 and ends when done reaches total, which is 0 while unknown. An open served from the cache reports nothing.
  • The callback runs on the thread doing the work while libtaco holds a lock, so calls from several threads never overlap. It must return normally and must not call taco_set_progress. The bindings swallow every error their bar raises; R evaluates its handler with R_tryEvalSilent so an R error cannot jump through libtaco.

Threads and shutdown

The header promises three things. taco_last_error belongs to the calling thread, the progress callback runs on the thread doing the work, and taco_shutdown() releases the transport resources the calling thread has cached. Call taco_shutdown before unloading the library; calling it twice is safe. The rest of this section is what the source does.

  • Each thread keeps its own Karu client and its connections, reused while the Karu settings read from the environment stay the same. taco_shutdown frees the calling thread's client; other threads free theirs when they exit.
  • The progress callback, the table of extracted local ZIPs and the table of cache snapshots are shared by the process and guarded by locks. A fork takes the two table locks first and gives the child fresh ones, and the child gets a fresh progress lock unless the forking thread is reporting progress.
  • A handle does not change after taco_open returns: the getters and taco_sql only read it. The header makes no promise about using one handle from several threads. Python uses one handle from several threads, with one DuckDB connection per thread.
  • Opening a remote FOLDER or TACOCAT, from the network or from the cache, starts short-lived threads that read up to eight object sizes at once.
  • The cache is shared between processes through the file system. An entry is assembled in a staging directory and renamed into place, so no reader sees half an entry. When several processes build the same entry at once, the first rename wins and the others use that entry, unless TACO_CACHE_REFRESH asks each for a rebuild. Each process reads its own snapshot of an entry, so a process that rebuilds or evicts the entry never changes what another one reads.
