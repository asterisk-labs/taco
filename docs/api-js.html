JavaScript

  • Package @asterisk-labs/taco on npm, an ES module for Node 20 or newer and modern browsers
  • Reader only, TACO 3.0.0
npm install @asterisk-labs/taco

The package reads FOLDER, ZIP and TACOCAT datasets over HTTP. It is pure JavaScript and loads neither libtaco nor DuckDB. It parses the cozip index of a ZIP itself, without @asterisk-labs/cozip, and decodes the metadata Parquet with hyparquet and hyparquet-compressors, its only dependencies. It exports openDataset, read, Dataset, TacoError and SUPPORTED_TACO_VERSION, which is "3.0.0". Types ship in types/index.d.ts. Samples, levels, locations and the other concepts every reader shares are on the API overview.

Compared with the bindings that load libtaco:

  • There is no sql() and no inspect(). Rows are selected with filter objects and raw level reads, and the contract is on the opened Dataset.
  • Sources are HTTP(S) URLs only. There are no local paths, no s3:// or hf:// prefixes and no source lists.
  • Nothing is cached on disk. A Dataset keeps what it fetched in memory.
  • Besides the wide view of read(), it has a long view with one row per file.

This page follows the source in the repository. The 0.14.2 release on npm lacks TacoAsset.byteLength and TacoAsset.read, their signal and maxFullBytes options, and the ETag check described under Caching.

Sources

A source is an absolute http:// or https:// URL in ASCII. Any other scheme fails with INVALID_URL, and a relative path throws TypeError. This holds in Node too, so a local dataset has to be served over HTTP. Use the HTTPS form of a remote store, such as https://data.source.coop/..., a Hugging Face resolve URL or a presigned URL. The prefixes and credentials of the native readers are under Sources on the overview.

With container: "auto", the default, the reader decides from the URL and the first responses:

  1. A path that ends in .zip, in any case, is opened as a ZIP.
  2. A path that ends neither in / nor in .tacocat is tried as a ZIP first. If the server answers 404, or the bytes are not a cozip archive (ARCHIVE_TOO_SMALL, TRUNCATED_INDEX, INVALID_INDEX), it is treated as a directory. Any other error is raised.
  3. For a directory the reader fetches COLLECTION.json. The dataset is a TACOCAT if the collection has taco:sources, and a FOLDER otherwise. If the file is missing, the reader tries .tacocat/COLLECTION.json, so the dataset directory and its .tacocat/ folder both open, as section 7.5 requires.

Passing "zip", "folder" or "tacocat" skips the guessing. A hint that does not match the collection fails with CONTAINER_MISMATCH. The containers themselves are described under Containers.

A ZIP must be a cozip archive with binary version 1 and profile 2. The reader checks the integrity hash over the index and the last 32 KiB before it trusts an offset, and requires the index to list exactly COLLECTION.json and one METADATA/<level>.parquet per level. Every collection must declare "taco:version": "3.0.0", and every level file must store its level name under the Parquet key taco:level. In a TACOCAT, partition paths resolve against the directory that holds .tacocat/.

Opening a dataset

openDataset

openDataset(source, { container = "auto", fetch, requestInit } = {}) -> Promise<Dataset>
sourceAn absolute HTTP(S) URL, as described under Sources.
container"auto", "zip", "folder" or "tacocat". Any other value throws TypeError.
fetchA function with the signature of fetch, used for every request. The default is globalThis.fetch, and without either the call fails with NO_FETCH.
requestInitAn object spread into every request, for headers such as Authorization or options such as credentials, cache or signal. The method is always GET, the reader adds its own Range header, and a body throws TypeError.

Options must be an object. Opening reads the collection, and for a ZIP the cozip index, but no Parquet. Each level is fetched the first time a call needs it.

import { openDataset } from "@asterisk-labs/taco";

const url = "https://data.source.coop/major-tom/core-dem/core-dem_MT3000km_0001D_0003L.zip";
const dataset = await openDataset(url);

console.log(dataset.container, dataset.levels, dataset.structure);
console.log(dataset.collection.id, dataset.collection["taco:version"]);
console.log(await dataset.levelRowCount("sample"));
zip [ 'sample', 'children' ] [ 'dem.rumi' ]
major-tom-core-dem 3.0.0
50178

This is one partition of Major TOM Core-DEM on Source Cooperative, 1,231,271,133 bytes with one dem.rumi elevation file per sample. The examples below continue from it.

sources[url].

The methods are read, readLevel, levelRowCount, cacheLevel and resolveAsset. The constructor is internal, so create a Dataset with openDataset.

Reading samples

dataset.read

dataset.read({ layout = "wide", idx = null, files = null, location = true, filter, level = null } = {}) -> Promise<object[]>
layout"wide" gives one row per sample and "long" one row per file. Any other value throws TypeError.
idxOne sample index, or a half-open range [start, end]. A negative or fractional value throws TypeError, and a start after the end throws RangeError. By default every sample is read.
filesAn array of structure declarations, as under Read. A name that is not in dataset.structure fails with INVALID_FILES.
locationA boolean. With false, a wide read skips the file levels and fills the file columns with null. A long read still returns one row per file, with taco:location set to null.
filterA filter object, applied to the finished rows. See Filters.
levelA level name. The call then returns the raw rows of that level, as readLevel does, with idx as a row range and filter passed to the Parquet reader. layout, files and location are ignored.

Rows come in sample order. A wide row follows the column order under Read: source_file for a TACOCAT, taco:sample_index, id, the sample metadata in sample.parquet order, then for each selected file its ::location column and the Rumi columns that follow it. Internal columns are left out. A variable sequence becomes one array column named after its prefix, ordered by index, and an empty array when a sample has none of its files.

const [row] = await dataset.read({ idx: 0 });
console.log(Object.keys(row).length, Object.keys(row).slice(-8));
console.log(row["dem.rumi::location"]);

The long view is specific to this package. Each row has source_file for a TACOCAT, taco:sample_index, id, path (the file's path in the structure), taco:location, then the metadata of the file, of its folders and of its sample. When a field is declared at several levels, the nearest one wins.

const files = await dataset.read({ layout: "long", idx: [0, 2] });
for (const file of files) console.log(file["taco:sample_index"], file.path, file["taco:location"]);

Cost

In a ZIP or FOLDER, idx becomes a Parquet row range. In a TACOCAT it is matched against internal:current_id after the whole sample level has been read, so even one sample downloads and decodes all of them. On the Core-DEM TACOCAT, read({ idx: 0, location: false }) made 67 requests for 37,619,353 bytes, took 52 s here and peaked at 2.97 GB of memory. To read a few samples of a large TACOCAT, find them with readLevel, whose row ranges and filters stay cheap, then open the partition ZIP named by their internal:source_file, which sits next to .tacocat/, and read them there.

read matches each file level to its samples with an $in filter on internal:parent_id, which slows down as the number of samples grows. With both levels of the partition already in memory, read({ idx: [0, 1000] }) took 120 ms here and read() of all 50,178 samples took 12.3 s, while readLevel returned the whole sample level in 187 ms and the whole children level in 56 ms.

read

read(source, { container, fetch, requestInit, layout, idx, files, location, filter, level } = {}) -> Promise<object[]>

Opens source with the options of openDataset and calls dataset.read with the rest. files is an option here, not a second argument as in read(source, files) of section 8.2. Each call opens the dataset again and keeps nothing, so open a Dataset to read more than once.

Metadata levels

readLevel

dataset.readLevel(level, { columns, filter, rowStart, rowEnd, rowIndexes } = {}) -> Promise<object[]>

Returns the stored rows of one level, with their internal:* columns and without any location. Stored columns named cozip:location or taco:location are dropped, because readers compute locations. It takes the place of the raw level relations of SQL.

levelOne of dataset.levels. Any other name fails with UNKNOWN_LEVEL.
columnsAn array of column names to decode, in that order. An unknown name rejects with hyparquet's Error: parquet column not found, which has no code.
filterA filter object, passed to hyparquet. See Filters.
rowStart, rowEndA half-open row range. A negative value, or a start after the end, throws RangeError.
rowIndexesAn array of row numbers, returned in the given order. It cannot be combined with rowStart, rowEnd or filter (TypeError), and a number past the last row throws RangeError.
const [child] = await dataset.readLevel("children", {
  columns: ["internal:parent_id", "internal:relative_path", "internal:offset", "internal:size"],
  rowStart: 0,
  rowEnd: 1,
});
console.log(child);
{
  'internal:parent_id': 0n,
  'internal:relative_path': '0/dem.rumi',
  'internal:offset': 224n,
  'internal:size': 28818n
}

levelRowCount

dataset.levelRowCount(level) -> Promise<number>

Returns the row count from the Parquet footer of the level, without decoding rows. The footer costs one request for the last 512 KiB of the file, plus one byte to learn its size in a FOLDER or TACOCAT.

cacheLevel

dataset.cacheLevel(level, { onProgress } = {}) -> Promise<ArrayBuffer>

Downloads the whole Parquet file of a level in one request and keeps it in memory, so later reads of that level make no requests. The promise resolves to the Parquet bytes, which the reader keeps using, so do not modify them. onProgress receives { loaded, total } at most every 100 ms and once at the end. A second call returns the same buffer.

const parquet = await dataset.cacheLevel("sample");
console.log(parquet.byteLength);
1309304

Filters

A filter is an object in the style of a MongoDB query:

  • { field: value } keeps rows whose value equals value. Several fields in one object must all match.
  • { field: { $gt: value } } compares, with $gt, $gte, $lt, $lte, $eq and $ne. $in and $nin take an array, and $not takes a nested condition.
  • { $and: [...] }, $or and $nor take an array of filters and must be the only key of their object.

An unknown operator fails with INVALID_FILTER. In readLevel, a filter on cozip:location or taco:location fails with PROTECTED_COLUMN.

The two methods apply a filter in different places. readLevel hands it to hyparquet, which skips row groups whose statistics rule it out and fetches only the pages it needs. read applies it to the finished rows, so it saves no reading, but it can test generated columns such as dem.rumi::mean.

const high = await dataset.readLevel("sample", {
  columns: ["internal:current_id", "id", "geoenrich:elevation"],
  filter: {
    "geoenrich:admin_countries": "Peru",
    "geoenrich:elevation": { $gt: 4500 },
  },
});
const top = high.reduce((a, b) => (b["geoenrich:elevation"] > a["geoenrich:elevation"] ? b : a));
console.log(high.length, top);
492 {
  'internal:current_id': 28679n,
  id: 'MT10km_0137D_0827L',
  'geoenrich:elevation': 5634.9560546875
}

Filter columns need not be in columns. On the whole TACOCAT the same filter returns the same 492 samples after reading 2,024,940 of the 37,294,786 bytes of sample.parquet, as traced under Requests.

hyparquet compares values with JavaScript's own operators, so in readLevel compare a 64-bit integer column with a BigInt. Here { "internal:current_id": 28679 } returned no rows and { "internal:current_id": 28679n } returned one. read treats a BigInt and a Number of the same value as equal.

SQL

The package has no sql() and loads no SQL engine, so the relations described under SQL are not available. readLevel and filters cover raw access and row selection. The playground runs SQL in the browser with DuckDB-Wasm, as described under Playground.

Rows

Rows are plain objects. hyparquet decides the JavaScript type of each stored value:

  • taco:sample_index is a Number. The reader converts it and fails with UNSAFE_INTEGER above 253 - 1.
  • Other 64-bit integers are BigInt, inside lists too: internal:offset is 224n and spatial:proj_shape is [352n, 352n]. Arithmetic that mixes BigInt and Number throws TypeError.
  • Floats and doubles are Numbers, and strings are strings. Binary values are Uint8Array, such as the 37 bytes of dem.rumi::header. Structs are objects, such as spatial:centroid, { lon, lat }, and lists are arrays.
  • A null value is null, but a null list can come back as undefined, as spatial:bbox does in Core-DEM.
  • A location in a ZIP or TACOCAT is /vsisubfile/{offset}_{size},/vsicurl/{url}. In a FOLDER it is /vsicurl/ followed by the file's URL under DATA/, with each path component percent-encoded.

Reading a file

resolveAsset

dataset.resolveAsset(location) -> TacoAsset

Turns a location into an object that fetch can read, without a request. It accepts /vsisubfile/{offset}_{size},/vsicurl/{url}, /vsicurl/{url} or a plain HTTP(S) URL. Another scheme fails with INVALID_URL, and a bad offset or size with INVALID_LOCATION. How the other bindings open a file is under Files.

TacoAsset

urlThe HTTP(S) URL of the object that holds the file: the ZIP for a ZIP or TACOCAT, the file itself for a FOLDER.
offset, sizeNumbers for a file inside a ZIP, null for a FOLDER file.
byteLength(options)Resolves to the size of the file. Inside a ZIP it comes from the location, with no request. A FOLDER file costs one request for its first byte.
read(offset, length, options)Resolves to a Uint8Array of length bytes from offset within the file, fetched with one range request. A range outside the file throws RangeError.
arrayBuffer()Resolves to the whole file, from one range request, or from one plain GET for a FOLDER file.
blob(type)Resolves to the same bytes as a Blob of that type, "application/octet-stream" by default.

The options of byteLength and read are { signal, maxFullBytes }. signal is an AbortSignal for that call, combined with any signal in requestInit. maxFullBytes caps the download when a server ignores Range and sends the whole object: a larger response fails with FULL_RESPONSE_TOO_LARGE.

const [peak] = await dataset.read({ idx: Number(top["internal:current_id"]) });
const asset = dataset.resolveAsset(peak["dem.rumi::location"]);
console.log(asset.offset, asset.size, asset.url);

const magic = await asset.read(0, 4);
const bytes = await asset.arrayBuffer();
console.log(new TextDecoder().decode(magic), bytes.byteLength);
764362320 42283 https://data.source.coop/major-tom/core-dem/core-dem_MT3000km_0001D_0003L.zip
RUMI 42283

Reads never leave the file, even inside a ZIP. A file of a ZIP dataset carries the archive's size and ETag from opening, so reading it after the archive was replaced fails with SOURCE_CHANGED. Payloads are opaque bytes to this package. The playground decodes Rumi files with @asterisk-labs/rumi.

Requests run in order, and the reader checks each Content-Range against the range it asked for. Opening the ZIP takes three:

  1. The first 64 KiB, for the local header and the cozip index, which gives the offsets of COLLECTION.json and the level files.
  2. The last 32 KiB, for the integrity hash.
  3. COLLECTION.json, 7,033 bytes at offset 1,225,322,417.

The first read of a level fetches the last 512 KiB of its Parquet file for the footer, which is hyparquet's default, then the pages it needs: 263,963 bytes of sample.parquet for sample 28679, and 275,479 bytes of children.parquet for its file row. The file itself is one request of exactly its 42,283 bytes. The eight requests moved 1,735,638 bytes of the 1,231,271,133-byte archive.

Caching

  • Everything is kept in memory, in the Dataset. Nothing is written to disk, and the cache variables under Sources do not apply. Each openDataset, and each call of the read function, starts again.
  • The footer of each level is fetched once per Dataset.
  • Pages are not kept. Reading sample 1 right after sample 0 fetched the same two page ranges again.
  • cacheLevel keeps a whole level, and later reads of it make no requests.
  • When a server answers a range request with 200 and the whole object, the reader keeps that body and serves later reads of the object from it.
  • requestInit reaches every request, so an option such as cache applies to all of them.

An open Dataset is a snapshot. The reader remembers the size and ETag of each object from its first response. A later response with another size or ETag, or a 412, fails with SOURCE_CHANGED. The reader does not send If-Match.

Errors

Wrong argument types throw TypeError and numbers out of range throw RangeError, with messages that start with taco:. Everything else throws TacoError, whose name is "TacoError", whose code names the problem, and whose message starts with taco CODE:. Errors from hyparquet, such as an unknown column, are plain Error without a code. The errors of the native readers are under Errors on the overview.

  "./dataset.zip",

for (const source of sources) {
  try {
    await openDataset(source);
  } catch (error) {
    console.log(error instanceof TacoError, error.name, error.code, error.message);
  }
}

In the browser

The package needs no build step. A page can import it from a CDN that bundles hyparquet with it, such as jsDelivr:

import { openDataset } from "https://cdn.jsdelivr.net/npm/@asterisk-labs/taco@0.14.2/+esm";

const url = "https://data.source.coop/major-tom/core-dem/core-dem_MT3000km_0001D_0003L.zip";
const dataset = await openDataset(url);
const [row] = await dataset.read({ idx: 28679 });
const bytes = await dataset.resolveAsset(row["dem.rumi::location"]).arrayBuffer();
console.log(row.id, bytes.byteLength);
MT10km_0137D_0827L 42283

That ran in a page served from http://localhost:8780. A page can also import src/index.js and map hyparquet and hyparquet-compressors with an import map, as the playground does, or let a bundler resolve them after npm install.

The server must meet the hosting requirements. In a browser these points matter to this reader:

  • CORS must allow a GET with a Range header from the page's origin, and any header passed in requestInit.
  • Content-Range must be listed in Access-Control-Expose-Headers. Without it every 206 fails with INVALID_RANGE.
  • Expose ETag too, or the reader cannot tell when an object changes.
  • A server that ignores Range still works, because the reader takes the whole object from the first 200 and slices it. Bound file downloads with maxFullBytes.

Source Cooperative answers with Access-Control-Allow-Origin: * and Access-Control-Expose-Headers: *, so its datasets open from any page.

Playground

The playground is a page built on this package. It imports src/index.js from the site, where make site copies it, and loads hyparquet 1.30.0 and hyparquet-compressors 1.1.1 from jsDelivr through an import map. Before calling the package it rewrites source.coop links to data.source.coop and Hugging Face tree and blob links to resolve links; the package itself takes a URL as given. For each dataset it:

  1. calls openDataset(url), then levelRowCount("sample"), and downloads the level with cacheLevel("sample", { onProgress }) to drive its progress bar.
  2. picks random rows and decodes only internal:current_id, the centroid and, in a TACOCAT, internal:source_file, with readLevel("sample", { columns, rowIndexes }), to draw the points.
  3. caches the other levels in the background with cacheLevel.
  4. shows the metadata of a clicked sample with readLevel and filters on internal:current_id and internal:parent_id, given as BigInt.
  5. downloads a file with resolveAsset(location).blob().
  6. previews a Rumi file with @asterisk-labs/rumi and its GeoZL WebAssembly decoder. It calls byteLength with maxFullBytes at 64 MiB, reads a file of up to 32 MiB (8 MiB on narrow screens) in one read(0, size), and hands a larger file to Rumi as a source whose reads call asset.read(offset, length), so only the ranges Rumi asks for are fetched.

The SQL tab is not part of the package. The playground loads DuckDB-Wasm 1.32.0 from jsDelivr, registers the cached sample.parquet bytes, and defines two views: sample, the raw level, and dataset, with source_file, taco:sample_index taken from the row number, id and the sample metadata, but no file columns. A query must return taco:sample_index, or internal:current_id when it reads sample, and the map then shows the matching samples.
