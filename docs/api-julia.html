Julia

  • Package Taco in the Asterisk registry, on Julia 1.10 or newer, with the native library for Linux x86-64 and aarch64, macOS x86-64 and arm64, and Windows x86-64.
  • Reader only
using Pkg
Pkg.Registry.add("General")
Pkg.Registry.add(Pkg.RegistrySpec(url = "https://github.com/asterisk-labs/AsteriskRegistry"))
Pkg.add("Taco")

The dependencies, such as DuckDB.jl and DataFrames.jl, come from the General registry. A new Julia installs General on its first Pkg.add, but not once another registry has been added, so add it first.

Taco.jl calls libtaco through ccall, runs queries with DuckDB.jl and returns DataFrames. It reads all three containers; the Python package writes them. See the API overview for the shared data model. This page covers Julia calls and behavior.

Nothing is exported. Call Taco.open_dataset, Taco.read, Taco.sql, Taco.inspect and Taco.read_bytes with the module name. using Taco brings only Taco into scope, so a bare read is still Base.read.

Native library

Taco.jl finds libtaco at the first call, not at using Taco, and takes the first of these that applies:

  1. TACO_LIB, the path of a build to load instead, such as the one make core writes to core/build/.
  2. core/build/libtaco.dylib, libtaco.so or taco.dll of the repository, when Taco.jl is loaded from a clone of it.
  3. The taco artifact in Artifacts.toml, the release archive of libtaco for the platform, downloaded on first use.

The binding requires C API version 3 and refuses any other. read_bytes also checks that the chosen library provides its functions. A library that cannot be loaded throws an ErrorException:

taco: could not load the TACO core from /nonexistent/libtaco.dylib: could not load library "/nonexistent/libtaco.dylib" ... Build it with `make core` or set TACO_LIB

A checkout of Taco.jl newer than the last release still names that release's archive in Artifacts.toml, which may carry an older C API. The error then says so and how to pair them:

taco: the TACO core at .../libtaco-0.14.2-macos-aarch64/lib/libtaco.dylib has C API 2, expected 3. The core is older than this Taco.jl, as happens when Taco.jl comes from a source checkout ahead of the last release. Build the core with `make core` and set TACO_LIB to it, or install a registered Taco release

The C page lists which C functions each binding calls.

Reading

open_dataset

Taco.open_dataset(source) -> Taco.Dataset

Opens a dataset and loads its collection and metadata. Payloads are not read.

sourceA string, or a vector of strings, in the source forms. A vector of two or more opens a source list. An empty vector, an empty string, a NUL byte, a repeated path, two paths to one file, or a value of another type throws ArgumentError. Paths are passed on as written, with a leading ~ expanded, so a relative path gives relative locations. Use abspath when the locations must work from another directory.
using Taco

url = "https://data.source.coop/major-tom/core-dem/core-dem_MT3000km_0001D_0003L.zip"
dataset = Taco.open_dataset(url)
dataset
Taco.Dataset("major-tom-core-dem", sources=1)

This partition of Major TOM Core-DEM holds 50,178 samples. Its first open fetched the metadata in 8.2 s here, and a second open read it from the cache in 0.89 s.

Dataset

struct Dataset
    sources::Vector{String}
    collection::Dict{String,Any}
    contract::Contract
    _opened::Vector{NativeDataset}
end

struct Contract
    structure::Vector{String}
    metadata::Dict{String,Any}
    levels::Vector{String}
end
sourcesThe paths given to open_dataset, as Strings, with a leading ~ expanded.
collectionCOLLECTION.json parsed by JSON3 into Dict{String,Any} and Vector{Any}. For a source list, the collection of the first source with the extents of all of them merged and their split:counts added up.
contractA Taco.Contract: structure, the declarations; metadata, the taco:metadata object, a Dict per level that does not keep the field order of COLLECTION.json; and levels, the level names in the order of COLLECTION.json.
_openedThe native handles, one per source, which read and sql reuse. A finalizer closes them.

read

Taco.read(source; files = nothing) -> DataFrame
Taco.read(dataset::Taco.Dataset; files = nothing) -> DataFrame

Returns one row per sample, with the columns Read describes. A path or a vector of paths is opened first, and a vector of two or more reads a source list.

filesnothing for every declaration, or a String or a vector of strings: full structure declarations, such as "before/B02.tif" or "img*[1,3].png". Only the selected files get :: columns; the metadata columns stay. An unknown declaration throws ErrorException, and an empty vector or an empty name ArgumentError.
samples = Taco.read(dataset)
size(samples)
(50178, 33)

The first read took 1.3 s here, most of it compiling, and later reads of the same dataset 0.09 s.

Taco.read returns rows in taco:sample_index order, for one source or a list. Releases up to 0.14.2 ordered only a source list. A query has no implicit order, so ask for it in SQL:

samples = Taco.sql(dataset, "SELECT * FROM dataset ORDER BY \"taco:sample_index\"")
samples[1, "taco:sample_index"]
Int(samples[1, "taco:sample_index"])
0x0000000000000000
0

DataFrame rows count from 1 and taco:sample_index from 0, so row 1 of the sorted table is sample 0. A UInt64 prints in hexadecimal on its own, and Int converts it.

sql

Taco.sql(dataset::Taco.Dataset, query::AbstractString) -> DataFrame

Runs one query over the dataset relation and one raw relation per level, as SQL describes. query holds one SELECT statement. Surrounding space and one trailing ; are removed, and an empty query or one containing NUL throws ArgumentError.

Field names go in double quotes, which a Julia string has to escape. A raw triple-quoted string, raw"""...""", holds them as written and does not interpolate $:

peaks = Taco.sql(dataset, raw"""
    SELECT id, "geoenrich:elevation", "dem.rumi::location"
    FROM dataset
    WHERE "geoenrich:admin_countries" = 'Peru' AND "geoenrich:elevation" > 4500
    ORDER BY "geoenrich:elevation" DESC
""")
peaks[1:3, 1:2]
3×2 DataFrame

─────┼─────────────────────────────────────────
   1 │ MT10km_0137D_0827L              5634.96
   2 │ MT10km_0174D_0779L              5533.95
   3 │ MT10km_0115D_0843L              5472.58

A column name with a colon is a string index, peaks[!, "geoenrich:elevation"], or a quoted property, peaks."geoenrich:elevation". A level relation keeps the internal columns and has no locations:

Taco.sql(dataset, raw"""
    SELECT "internal:current_id", "internal:offset", "internal:size", "rumi:mean"
    FROM children
    ORDER BY "internal:current_id"
    LIMIT 2
""")
2×4 DataFrame

─────┼────────────────────────────────────────────────────────────────
   1 │                   0              224          28818    323.236
   2 │                   1            29087          30332    340.349

read and sql share a locked DuckDB connection per process, closed at exit. It uses UTC and never installs extensions. Functions such as extract(year FROM ...) on timestamps with time zones need ICU, which can load from ~/.duckdb/extensions if already installed.

Queries run as SELECT * FROM (query) under a WITH defining the relations, so each query must be one statement.

inspect

Taco.inspect(source, query::AbstractString)

Reads one part of a dataset without reading its rows. source is one path or URL; a vector of two or a Taco.Dataset throws ArgumentError, and every call opens the source again. query is one of these strings, and any other throws ArgumentError:

"structure"Vector{String}, the structure declarations.
"levels"Vector{String}, the levels sorted by the core. It can differ from contract.levels: for a dataset with before/ and after/ folders it lists children/after before children/before. Look levels up by name.
"contract"A DataFrame of kind and value rows.
"collection"Dict{String,Any}, COLLECTION.json parsed as in open_dataset.
"profile"String, the cozip profile of an archive: "taco" for a TACO ZIP.
"native_sql"String, the SQL the core generates for the dataset view, for debugging only.

Column types

DuckDB.jl converts each column of a result:

uint64UInt64: taco:sample_index and the internal: columns.
int64Int64, count(*) included.
float, doubleFloat32, Float64.
stringString. Each ::location of a fixed file is one string.
timestamp[us, UTC]DateTime, holding the UTC time to the millisecond; epoch_us(column) in Taco.sql returns the stored microseconds.
binaryBase.CodeUnits{UInt8, String}, a read-only byte vector: a WKB geometry, a Rumi header. Vector{UInt8}(x) copies it.
list<T>Vector{Union{Missing, T}}. A sequence such as extra*[1,3].png gives extra::location, a Vector{Union{Missing, String}} of one to three paths.
structNamedTuple, such as (lon = -75.98052f0, lat = -12.260741f0).
row = Taco.sql(dataset, "SELECT * FROM dataset WHERE id = 'MT10km_0137D_0827L'")
for name in ["taco:sample_index", "spatial:centroid", "spatial:proj_shape", "dem.rumi::header", "geoenrich:elevation"]
    println(rpad(name, 21), eltype(row[!, name]))
end
taco:sample_index    UInt64
spatial:centroid     Union{Missing, NamedTuple{(:lon, :lat)}}
spatial:proj_shape   Vector{Union{Missing, Int64}}
dem.rumi::header     Base.CodeUnits{UInt8, String}
geoenrich:elevation  Float32

A column is Union{Missing, T} when its result holds a null, so one field can come back with two element types. geoenrich:elevation is Float32 in this one-row result and Union{Missing, Float32} in Taco.read(dataset), where some samples have no value.

Sources

Source lists and TACOCAT

A vector of ZIP partitions of one collection opens as one dataset, with a source_file column and taco:sample_index numbered across the list in list order, as Read describes.

base = "https://data.source.coop/major-tom/core-dem/"
parts = base .* ["core-dem_MT3000km_0001D_0003L.zip", "core-dem_MT3000km_0001D_0004L.zip"]
both = Taco.open_dataset(parts)
Taco.sql(both, "SELECT source_file, count(*) AS n FROM dataset GROUP BY source_file ORDER BY source_file")
2×2 DataFrame
 Row │ source_file                        n
     │ String                             Int64
─────┼──────────────────────────────────────────
   1 │ core-dem_MT3000km_0001D_0003L.zip  50178
   2 │ core-dem_MT3000km_0001D_0004L.zip   1631

A TACOCAT opens from its directory, and cannot be part of a list:

catalog = Taco.open_dataset("https://data.source.coop/major-tom/core-dem/")
Taco.sql(catalog, raw"""
    SELECT source_file, id, "geoenrich:elevation"
    FROM dataset
    WHERE "geoenrich:admin_countries" = 'Peru'
    ORDER BY "geoenrich:elevation" DESC
    LIMIT 1
""")
1×3 DataFrame
 Row │ source_file                        id                  geoenrich:elevation
     │ String                             String              Float32
─────┼────────────────────────────────────────────────────────────────────────────
   1 │ core-dem_MT3000km_0001D_0003L.zip  MT10km_0137D_0827L              5634.96

From the cache this TACOCAT opened in 3.4 s here, and Taco.read(catalog) returned all 1,735,044 rows in 7.5 s.

Cache

The core reads TACO_CACHE_DIR, TACO_CACHE_SIZE and TACO_CACHE_REFRESH from the environment at each open, under the rules of Sources and cache, so setting ENV before open_dataset is enough:

ENV["TACO_CACHE_DIR"] = "taco-cache"
dataset = Taco.open_dataset(url)
filter(!startswith("."), readdir("taco-cache"))
2-element Vector{String}:
 "CACHEDIR.TAG"
 "major-tom-core-dem-zip-https-815e5df3eedb"

The filter leaves out the names that start with a period: the snapshots that open datasets read, which the process removes when it exits.

Opening the files

A location is a VSI path, as Open a file explains.

read_bytes

Taco.read_bytes(location::AbstractString) -> Vector{UInt8}
Taco.read_bytes(locations::AbstractVector) -> Vector{Vector{UInt8}}

Returns the whole file as bytes, without GDAL. Pass a ::location value, a local path or a URL. A vector returns one byte vector per location, in input order; Karu groups the requests into bounded batches. ~ and ~/ are expanded.

The artifact currently listed in Artifacts.toml predates this function. In a source checkout, run make core before calling it, or set TACO_LIB to a newer build.

bytes = Taco.read_bytes(row[1, "dem.rumi::location"])
length(bytes), String(bytes[1:4])
(42283, "RUMI")

A location that cannot be resolved or read throws an ErrorException with the core's message.

Errors

Julia argument checks raise ArgumentError. Core failures and incompatible source lists raise ErrorException. Bad queries raise DuckDB.QueryException. The examples show each type and message; see Errors for causes.

ErrorException: taco: files contains unknown structure leaf: nope.rumi
ErrorException: could not open missing.zip: missing.zip: No such file or directory
ArgumentError: taco: source paths must be unique
ErrorException: taco: a source list cannot contain TACOCAT datasets
DuckDB.QueryException: Parser Error: syntax error at or near ":"
DuckDB.QueryException: Catalog Error: Table with name children/missing does not exist!

Julia strings are UTF-8 whatever the locale, so a path such as niño.zip opens under LC_ALL=C too.

Threads

Tasks can call Taco concurrently, including on their first call. With julia -t 4, 32 first reads of different ZIPs finished in 1.3 s across three runs, or 2.3 to 2.5 s while another task stressed the garbage collector. Version 0.14.2 could deadlock in this case.

Calls that may wait on core locks run in a GC-safe region, allowing collection to proceed. See Threads and shutdown for the core's locks.
