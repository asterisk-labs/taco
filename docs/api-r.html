R

  • Package taco on r-universe, with binaries for Linux, macOS and Windows, on R 4.3 or newer.
  • Reader only
install.packages("taco", repos = "https://asterisk-labs.r-universe.dev")

The R package compiles its bundled libtaco and Karu sources into one shared library. TACO_LIB is not used. Source installs need a C++23 compiler, pkg-config, libcurl 7.83+ and OpenSSL 3+. Queries use duckdb 1.5.5+ and return tibbles.

WebAssembly builds omit the core; calls there stop with the native TACO core is not available on WebAssembly.

The package exports open_dataset, read, sql, inspect and read_bytes. It reads all three containers; the Python package writes them. See the API overview for shared concepts. This page covers R calls and behavior.

Reading

open_dataset

open_dataset(source)

Opens a dataset, loads its collection and metadata, and returns a taco_dataset. Payloads are not read.

sourceA character vector of one or more paths or URLs, in the source forms. Two or more open a source list. An empty vector, an NA, an empty string or a repeated path, or two paths to one file such as a.zip and ./a.zip, stops with an error. Paths are passed on as written, with a leading ~ expanded, so a relative path gives relative locations. Use normalizePath() when the locations must work from another directory.
library(taco)

url <- "https://data.source.coop/major-tom/core-dem/core-dem_MT3000km_0001D_0003L.zip"
dataset <- open_dataset(url)
dataset
taco.Dataset(major-tom-core-dem, sources=1)

This partition of Major TOM Core-DEM holds 50,178 samples. Its first open fetched the metadata in 7.9 s here, and a second open read it from the cache in 0.98 s.

taco_dataset

A list of class c("taco_dataset", "list"). There is no dataset$read(): pass it to read and sql.

sourcesThe character vector given to open_dataset, with a leading ~ expanded.
collectionCOLLECTION.json parsed by jsonlite into nested lists, so collection$extent$spatial is a list of four numbers. For a source list, the collection of the first source with the extents of all of them merged and their split:counts added up.
contractA list of class taco_contract: structure, a character vector of declarations; metadata, the taco:metadata object, a named list per level whose fields hold type, nullable and description; and levels, the level names in the order of COLLECTION.json.
_openedThe native handles, one per source, which read and sql reuse. They close when the dataset is garbage collected.
dataset$contract$structure
dataset$contract$levels
names(dataset$contract$metadata$children)
dataset$collection$title
[1] "dem.rumi"
[1] "sample"   "children"
[1] "rumi:header"  "rumi:minimum" "rumi:maximum" "rumi:mean"    "rumi:stddev"
[6] "rumi:p2"      "rumi:p98"
[1] "Major TOM Core-DEM"

Printing shows the collection id and the number of sources. A dataset is a snapshot of the metadata it loaded, except a local FOLDER or TACOCAT, which is read in place (Sources and cache).

read

read(source, files = NULL)

Returns a tibble with one row per sample and the columns Read describes. read is an S3 generic with a method for a taco_dataset and one for a character vector, which opens the source first.

sourceA taco_dataset, or a character vector as for open_dataset.
filesNULL for every declaration, or a character vector of full structure declarations, such as "before/B02.tif" or "img*[1,3].png". Only the selected files get :: columns; the metadata columns stay. An unknown declaration stops with taco: files contains unknown structure leaf, and an empty vector, an NA or an empty string also stops with an error.
samples <- read(dataset)
dim(samples)
[1] 50178    33

That read took 0.30 s here.

The overview promises rows in taco:sample_index order. In 0.14.2 R keeps that promise only for a source list: for one source the query it runs has no ORDER BY, and this partition and the Core-DEM TACOCAT both came back out of order here. When the order matters, ask for it in SQL:

samples <- sql(dataset, 'SELECT * FROM dataset ORDER BY "taco:sample_index"')
samples[1:3, c("taco:sample_index", "id")]
# A tibble: 3 × 2
  `taco:sample_index` id
                <dbl> <chr>
1                   0 MT10km_0002D_0618L
2                   1 MT10km_0002D_0619L
3                   2 MT10km_0002D_0620L

Tibble rows count from 1 and taco:sample_index from 0, so row 1 of the sorted table is sample 0.

sql

sql(dataset, query)

Runs one query over the dataset relation and one raw relation per level, as SQL describes, and returns a tibble.

datasetA taco_dataset. A path stops with taco: `dataset` must be a taco_dataset.
queryOne string with one SELECT statement. Surrounding space and one trailing ; are removed, and an empty query stops with an error.

Field names go in double quotes and text in single quotes. An R raw string, r"(...)", holds both without escapes:

peaks <- sql(dataset, r"(
  SELECT id, "geoenrich:elevation", "dem.rumi::location"
  FROM dataset
  WHERE "geoenrich:admin_countries" = 'Peru' AND "geoenrich:elevation" > 4500
  ORDER BY "geoenrich:elevation" DESC
)")
nrow(peaks)
peaks[1:3, 1:2]
[1] 492

  id                 `geoenrich:elevation`
  <chr>                              <dbl>
1 MT10km_0137D_0827L                 5635.
2 MT10km_0174D_0779L                 5534.
3 MT10km_0115D_0843L                 5473.

A level relation keeps the internal columns and has no locations:

sql(dataset, '
  SELECT "internal:current_id", "internal:offset", "internal:size", "rumi:mean"
  FROM children
  ORDER BY "internal:current_id"
  LIMIT 2
')
# A tibble: 2 × 4
  `internal:current_id` `internal:offset` `internal:size` `rumi:mean`
                  <dbl>             <dbl>           <dbl>       <dbl>
1                     0               224           28818        323.
2                     1             29087           30332        340.

read and sql share one DuckDB connection per R session, opened on first use and closed when the package unloads or R exits. It uses UTC and never installs extensions. Functions such as extract(year FROM ...) on timestamps with time zones need ICU, which can load from DuckDB's extension directory (?duckdb_storage) if already installed.

Queries run as SELECT * FROM (query) under a WITH defining the relations, so each query must be one statement. DuckDB counts error lines from the start of that statement; the first line of a Core-DEM query appears as LINE 6.

inspect

inspect(source, query)

Reads one part of a dataset without reading its rows. source is one path or URL; a vector of two or a taco_dataset stops with an error, and every call opens the source again. query is one of these strings, and any other stops with an error:

"structure"A character vector of the structure declarations.
"levels"A character vector of the levels, sorted by the core. It can differ from contract$levels: for a dataset with before/ and after/ folders it lists children/after before children/before. Look levels up by name.
"contract"A tibble of kind and value rows.
"collection"A list, COLLECTION.json parsed as in open_dataset.
"profile"One string, the cozip profile of an archive: "taco" for a TACO ZIP.
"native_sql"One string, the SQL the core generates for the dataset view, for debugging only.
inspect(url, "contract")
inspect(url, "profile")
# A tibble: 3 × 2
  kind      value
  <chr>     <chr>
1 structure dem.rumi
2 level     sample
3 level     children
[1] "taco"

Column types

The duckdb package converts each column of a result:

uint64, int64Double, exact up to 253. This covers taco:sample_index, the internal: columns, count(*) and the items of a list<int64>.
float, doubleDouble.
stringCharacter. Each ::location of a fixed file is one string.
timestamp[us, UTC]POSIXct with tzone "UTC".
binaryA list of raw vectors, with NULL for a null value: a WKB geometry, a Rumi header.
list<T>A list of vectors. A sequence such as extra*[1,3].png gives extra::location, a list of character vectors of one to three paths.
structA data frame column, so row[["spatial:centroid"]]$lon.

Sources

Source lists and TACOCAT

A character vector of ZIP partitions of one collection opens as one dataset, with a source_file column and taco:sample_index numbered across the list in list order, as Read describes.

base <- "https://data.source.coop/major-tom/core-dem/"
parts <- paste0(base, c("core-dem_MT3000km_0001D_0003L.zip", "core-dem_MT3000km_0001D_0004L.zip"))
both <- open_dataset(parts)
both
sql(both, "SELECT source_file, count(*) AS n FROM dataset GROUP BY source_file ORDER BY source_file")
taco.Dataset(major-tom-core-dem, sources=2)
# A tibble: 2 × 2
  source_file                           n
  <chr>                             <dbl>
1 core-dem_MT3000km_0001D_0003L.zip 50178
2 core-dem_MT3000km_0001D_0004L.zip  1631

A TACOCAT opens from its directory, and cannot be part of a list:

catalog <- open_dataset("https://data.source.coop/major-tom/core-dem/")
sql(catalog, r"(
  SELECT source_file, id, "geoenrich:elevation"
  FROM dataset
  WHERE "geoenrich:admin_countries" = 'Peru'
  ORDER BY "geoenrich:elevation" DESC
  LIMIT 1
)")
# A tibble: 1 × 3
  source_file                       id                 `geoenrich:elevation`
  <chr>                             <chr>                              <dbl>
1 core-dem_MT3000km_0001D_0003L.zip MT10km_0137D_0827L                 5635.

The first open of this TACOCAT fetched 70 MB of metadata in 62 s here. read(catalog) then returned all 1,735,044 rows in 5.7 s.

Cache

The core reads TACO_CACHE_DIR, TACO_CACHE_SIZE and TACO_CACHE_REFRESH from the environment at each open, under the rules of Sources and cache, so Sys.setenv() before open_dataset is enough:

Sys.setenv(TACO_CACHE_DIR = "taco-cache")
invisible(open_dataset(url))
list.files("taco-cache")
[1] "CACHEDIR.TAG"
[2] "major-tom-core-dem-zip-https-815e5df3eedb"

Opening the files

A location is a VSI path, as Open a file explains. Core-DEM stores Rumi files, which the rumi package, from the same r-universe, decodes with the header the dataset keeps beside each one:

dem <- rumi::rumi_read(row[["dem.rumi::location"]], row[["dem.rumi::header"]][[1]])
dim(dem)
range(dem)
[1] 352 352   1
[1] 4220 5872

read_bytes

read_bytes(location)

Returns the whole file as raw bytes, without GDAL. location accepts a character vector of ::location values, local paths or URLs. One location returns a raw vector; any other length returns a list in input order. Karu groups the requests into bounded batches. A leading ~ is expanded.

bytes <- read_bytes(row[["dem.rumi::location"]])
length(bytes)
rawToChar(bytes[1:4])
[1] 42283
[1] "RUMI"

A location that cannot be resolved or read raises an error with the core's message.

Errors

R checks and core failures raise simpleError, usually with a taco: message. DuckDB query failures raise rlang_error with the DuckDB error type in the message. Catch either with tryCatch(..., error = function(e) ...) and read conditionMessage(e). See Errors for causes.

taco: files contains unknown structure leaf: nope.rumi
could not open missing.zip: missing.zip: No such file or directory
taco: `source` paths must be unique
taco: a source list cannot contain TACOCAT datasets
Parser Error: syntax error at or near ":"
Catalog Error: Table with name children/missing does not exist!

The parser error comes from an unquoted field, WHERE geoenrich:elevation > 4500, and the catalog error from a level that does not exist.

Locale

Use a UTF-8 locale. Under LC_ALL=C, R turns a non-ASCII path such as niño.zip into the text ni<c3><b1>o.zip before it reaches the core, and the open fails with No such file or directory. In a UTF-8 locale the same path opens. Sys.getlocale("LC_CTYPE") shows the current one.
